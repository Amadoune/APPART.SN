# A-5.3-MODERATION-QUEUE-OWNER-READ-SOURCE-01 — Risk Assessment

| Risque | Gravité | Traitement futur obligatoire |
|---|---:|---|
| scan croissant avec filtre catégorie | élevée | index additif couvrant catégorie et ordre |
| curseur réutilisé avec d'autres filtres | élevée | checksum des filtres dans le curseur |
| altération du curseur | élevée | protection canonique et résultat `InvalidCursor` |
| fuite de `claim_owner_id` ou `lease_id` | critique | exclusion du mapper public |
| pagination par offset | élevée | keyset exclusivement |
| ordre non total | élevée | terminaison par `queue_item_id` |
| mutation depuis une Query | critique | port read-only séparé |
| accès au checkpoint | moyenne | exclusion contractuelle et Architecture test |
| doublon entre pages sous concurrence | moyenne | prédicat keyset strict |
| lecture devenue autorité métier | critique | projection informative, aucune décision |

## PostgreSQL

La lecture par état peut utiliser l'index existant. Le filtre catégorie exige un
plan de preuve spécifique : `EXPLAIN`, volumétrie représentative, pagination
successive et concurrence lecture/mutation.

Une migration additive d'index est préférable à l'acceptation d'un plan pouvant
balayer un grand sous-ensemble d'état. Elle ne devra être créée qu'après
ouverture explicite d'une Foundation technique.

## Risque résiduel du Discovery

Aucun risque bloquant n'empêche de définir et d'implémenter ultérieurement la
source. Le principal choix restant est normatif : rendre le filtre catégorie
obligatoire et créer son index, ou le retirer du contrat V1.
