# A-5.3-MODERATION-HTTP-READ-BOUNDARIES-01 — Query Matrix

| Query | Owner | Données minimales | Données interdites | Source requise | État |
|---|---|---|---|---|---|
| Own Report | ModerationReports | statut agrégé, horodatage publiable, action attendue | acteurs, preuves, constats, décision interne | lookup durable `reportId → caseId` puis vue filtrée | manquante |
| Queue | ModerationReports.Queue | items minimaux, lease publiable, cursor, checkpoint opaque | snapshot complet, SQL, diagnostic | source de liste avec filtres/cursor/limit | manquante |
| Case | ModerationReports | cible opaque, version, éléments autorisés, handoff public | intent checksum, diagnostics, colonnes | case store owner-local derrière reader | disponible |
| Decision | ModerationReports | disposition, action, policy version, état d'application | payload Outbox, SQL, historique non autorisé | decision store owner-local derrière reader | disponible |

## Atomicité et concurrence

Toutes les Queries sont read-only. Elles n'ouvrent aucune transaction métier,
ne prennent aucun advisory lock et ne modifient aucun checkpoint. Une vue
incohérente ou une dépendance indisponible produit un résultat fail-closed.

## Décision d'implémentation

La création des deux readers faisables seulement serait une implémentation
partielle interdite. Les quatre ports resteront absents jusqu'à certification
des deux sources owner.
