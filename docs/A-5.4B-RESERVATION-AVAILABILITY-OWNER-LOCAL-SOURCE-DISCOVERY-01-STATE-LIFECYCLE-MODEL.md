# A-5.4B Reservation Availability Source — State and Lifecycle Model

## États conceptuels persistables

| État interne candidat | Signification | Bloque une fenêtre |
|---|---|---|
| `Proposed` | tentative enregistrée, sans acquisition | non |
| `Held` | fenêtre acquise temporairement par l'owner | oui |
| `Committed` | occupation liée à une réservation acceptée | oui |
| `Released` | occupation libérée | non |
| `Expired` | hold arrivé à échéance | non |

Ces noms sont conceptuels et ne constituent pas un enum ou un lifecycle
certifié. Leur matérialisation exigera une Contracts/Persistence Foundation.

## Résultats de lecture non persistés

- `Available` : aucun état bloquant cohérent ne chevauche la fenêtre ;
- `Conflicting` : au moins un état bloquant cohérent la chevauche ;
- `Missing` : l'intent ou le sujet attendu n'est pas matérialisé ;
- `Corrupted` : continuité, checksum ou projection incohérents ;
- `DependencyUnavailable` : source technique indisponible.

Ces cinq résultats sont des réductions déterministes. Ils ne sont jamais
écrits comme autorité dans le journal.

## Transitions candidates

`Proposed -> Held -> Committed -> Released` et `Held -> Expired` sont les seuls
chemins conceptuellement nécessaires. Aucune transition n'est ouverte ou
implémentée par ce Discovery.
