## Compatibilité structurelle

- `ListingId` existant est réutilisé ; aucune identité concurrente n'est créée ;
- la fraîcheur utilise le nouveau Value Object public
  `ContactabilityObservedAt` ;
- aucune migration ou persistence n'est nécessaire pour le contrat ;
- aucun Provider, binding ou Runtime ne rend le reader exécutable ;
- aucune projection n'est promue au rang d'autorité ;
- aucun consumer n'est ouvert implicitement.

## Conclusion

L'amendement ajoute uniquement une frontière contractuelle. Toute
implémentation owner et toute consommation ContactsLeads requièrent des
décisions d'autorité distinctes.

## Extension Owner Implementation

L'Owner Implementation réutilise uniquement
`ListingPublicationWorkflowStore::read(ListingId)`. F-01, F-19/F-20, Public
Projection, Search, Listing Moderation, ContactsLeads, Runtime Health,
migrations Listing et Phase 5.3 restent inchangés. Le binding est limité au
Provider de composition existant et ne crée aucune capacité Runtime.
