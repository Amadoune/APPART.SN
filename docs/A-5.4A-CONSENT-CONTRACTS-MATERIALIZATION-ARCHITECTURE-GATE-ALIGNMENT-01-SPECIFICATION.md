# Architecture Gate Alignment Specification

## Cause racine

La gate Contracts Materialization interdisait historiquement tout binding de
`LeadContactConsentReaderV1` dans l'ensemble du dépôt. Cette portée globale,
correcte lors de la matérialisation contractuelle, est devenue incompatible
avec l'Owner Reader explicitement autorisé.

## Règle bornée

- l'enclave `ConsentPublicRead` reste limitée aux quatre contrats et Value
  Objects certifiés ;
- aucun Owner Reader n'est placé dans cette enclave ;
- le seul Provider autorisé à binder le contrat public est
  `ContactsLeadsConsentOwnerReaderServiceProvider` ;
- l'unique implémentation autorisée est
  `OwnerLeadContactConsentReaderV1` ;
- cette implémentation dépend de `ConsentOwnerSourceRuntimeReadV1` et jamais de
  Persistence ou Infrastructure.
