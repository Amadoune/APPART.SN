# A-5.4B Reservation Availability Persistence — Idempotence & Concurrency

| Situation | Résultat |
|---|---|
| même intent/révision/checksum | `AlreadyApplied` |
| même intent/révision, contenu différent | `DivergentRevision` |
| révision non continue ou transition invalide | `VersionConflict` |
| acquisition chevauchant une occupation active | `AvailabilityConflict` |
| deux appends identiques concurrents | un `Applied`, un `AlreadyApplied` |

La transaction prend un advisory lock PostgreSQL borné au sujet owner-local,
puis relit l'historique applicable avant tout `Held` ou `Committed`. Les
transactions englobantes utilisent un savepoint ; toute erreur revient au
savepoint ou annule la transaction owner-locale complète.
