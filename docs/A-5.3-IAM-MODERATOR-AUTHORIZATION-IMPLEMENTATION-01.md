# A-5.3-IAM-MODERATOR-AUTHORIZATION-IMPLEMENTATION-01

## Statut

AMENDEMENT OUVERT — REPRÉSENTATION GO PROPOSÉE

## Implémentation owner

`OwnerModeratorAuthorizationReaderV1` implémente sans modification le contrat
`ModeratorAuthorizationReaderV1`.

Sa seule dépendance est `AccountRegistry`, port Application owner IAM déjà
certifié. Le Reader n'expose jamais l'Aggregate retourné par cette source et
n'effectue aucune écriture.

## Politique fermée

| Capability | Rôle IAM actif requis |
|---|---|
| Report | `moderator` |
| Validate | `moderator` |
| Investigate | `moderator` |
| Decide | `moderator` |
| Audit | `moderation_auditor` |

Ces identifiants sont lus exclusivement. L'amendement ne crée, ne renomme et ne
modifie aucun rôle.

`Account::hasRole()` applique les règles IAM existantes : un assignment révoqué
ou un compte suspendu n'autorise jamais l'action.

## Résultats

- source trouvée, identité cohérente et rôle actif : `Allowed` ;
- compte absent ou rôle absent/inactif : `Denied` ;
- identité incohérente renvoyée par la source owner : `Corrupted` ;
- source owner en échec : `DependencyUnavailable`.

Seul `Allowed` autorise l'action.

## Runtime

`ModeratorAuthorizationServiceProvider` enregistre :

- `OwnerModeratorAuthorizationReaderV1` comme singleton lazy ;
- un alias unique vers `ModeratorAuthorizationReaderV1`.

Runtime Health reste inchangé.

## Hors périmètre

- migration ou Persistence ;
- modification d'Account ou des rôles ;
- HTTP ;
- Event, Delivery ou Outbox ;
- ModerationReports ;
- Command Handoff ;
- ouverture de 5.3I.
