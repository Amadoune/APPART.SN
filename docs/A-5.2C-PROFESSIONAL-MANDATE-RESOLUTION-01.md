# A-5.2C-PROFESSIONAL-MANDATE-RESOLUTION-01

## Statut

**BOUNDARY AUDIT OUVERT — CONCLUSION NO GO PROPOSÉE.**

Audit strictement documentaire. Aucun artefact technique n’est créé ou
modifié.

## Chaîne d’autorité auditée

```text
AccountId IAM
→ identité de représentant
→ mandat actif
→ établissement
→ ProfessionalId
```

## Ownership constaté

| Élément | Owner |
|---|---|
| `AccountId`, session et disponibilité du compte | F-17 Identity & Access |
| `RepresentativeId` | Professional Core |
| `RepresentativeMandate` | Aggregate historique `Professional` |
| appartenance de l’établissement | Aggregate historique `Professional` |
| association finale du mandat au `ProfessionalId` | Aggregate historique `Professional` |

F-17 ne possède ni mandat, ni établissement, ni `ProfessionalId`.
Professional Core possède la relation métier du mandat, mais ne possède
actuellement aucune frontière publique reliant explicitement un `AccountId`
typé à son `RepresentativeId`.

## État réel du modèle

`RepresentativeMandate` contient :

- `MandateId` ;
- `EstablishmentId` ;
- `RepresentativeId` ;
- `MandateRole` ;
- dates d’attribution et de révocation.

Il ne contient aucun `AccountId`. `RepresentativeId` est un identifiant opaque
alphanumérique et non un alias typé ou certifié d’`AccountId`.

Assimiler leurs valeurs serait une nouvelle règle métier implicite. Le
Discovery indique conceptuellement que le représentant est référencé par un
identifiant IAM, mais aucun contrat, invariant de typage, mapping ou preuve de
certification ne matérialise cette relation.

## Inventaire des frontières existantes

### `ProfessionalRegistry`

Le registre historique permet uniquement :

- `find(ProfessionalId)` ;
- ajout et sauvegarde de l’Aggregate ;
- réservation d’un établissement.

Il ne permet pas une query par `RepresentativeId` ou `AccountId`. Il expose en
outre un Aggregate mutable et constitue une persistence owner, pas une vue
publique d’autorisation.

### Use cases de mandat

`GrantMandate` et `RevokeMandate` sont des commandes. Ils requièrent déjà le
`ProfessionalId` et ne résolvent pas un compte authentifié.

### Events de mandat

`MandateGranted` et `MandateRevoked` contiennent `RepresentativeId`, mais pas
`AccountId`. Leur replay ou leur projection locale est explicitement interdit
et ne fournirait ni bootstrap, ni autorité courante certifiée.

### IAM

La session certifiée fournit uniquement `AccountId`. `AccountRegistry`,
Account Availability et les stores IAM ne connaissent ni `RepresentativeId`,
ni mandat, ni `ProfessionalId`.

## Réponses obligatoires

| Question | Conclusion |
|---|---|
| Quel domaine possède la relation ? | Professional Core possède les mandats et leur association au Professional ; IAM possède seulement Account. Le lien typé Account → Representative n’est pas matérialisé. |
| Existe-t-il un contrat public certifié ? | Non. |
| La résolution est-elle possible sans SQL direct ? | Non avec la baseline actuelle. |
| Les frontières IAM et Professionals sont-elles préservées ? | Oui seulement en refusant toute assimilation ou lecture directe ; une future query owner Professional peut les préserver. |
| La résolution est-elle déterministe et fail-closed ? | Aucun mécanisme existant ne le démontre. |
| Une consommation cross-domain est-elle déjà autorisée ? | Non. Les documents n’autorisent qu’une future consommation par contrat public. |
| Un nouvel amendement est-il nécessaire ? | Oui. |

## Frontière minimale requise

Un amendement ultérieur devra définir une query publique versionnée, owner
Professional Core, prenant un `AccountId` certifié et retournant un résultat
fermé, par exemple conceptuellement :

```text
Resolved(ProfessionalId, permissions minimales)
NotMandated
Ambiguous
Corrupted
DependencyUnavailable
```

La résolution devra considérer uniquement les mandats actifs et ne jamais
exposer l’Aggregate, les établissements complets, l’historique ou les données
IAM. Tous les résultats autres que `Resolved` devront être fail-closed.

Cette forme est descriptive et ne crée aucun contrat normatif.

## Impacts de l’audit

| Surface | Impact |
|---|---|
| IAM F-17/F-18 | aucun |
| Professional Aggregate / mandates | aucun |
| Runtime / HTTP 5.2C | aucun ; HTTP reste bloqué |
| persistence / migrations | aucun |
| Event / Delivery / Outbox | aucun |

## Conclusion

**NO GO.**

Aucun contrat public certifié ne résout `AccountId → mandat actif →
ProfessionalId`. Un amendement versionné d’extension de Professional Core est
nécessaire.
