# A-5.1-IAM-PERSISTENCE-BOUNDARY-01 — Boundary Audit

## Cause

Le port `OwnerPersistenceStore`, déclaré dans Application, importait un type
concret déclaré dans Infrastructure. La règle d'architecture
`test_application_does_not_depend_on_infrastructure` détectait correctement
l'inversion.

Le défaut était exclusivement structurel :

- aucun SQL erroné ;
- aucun owner dupliqué ;
- aucun changement de résultat fermé ;
- aucun défaut de concurrence ou de rollback ;
- aucune implication pour les migrations 044–052.

## Frontière corrigée

Application possède désormais le langage du port :

- `OwnerPersistenceStore` ;
- `OwnerPersistenceState` ;
- `PersistenceWriteResult`.

Infrastructure possède :

- le mapper row/state ;
- les stores PostgreSQL ;
- les détails PDO, SQL, transactions et types PostgreSQL.

Application ne référence plus aucun namespace `Infrastructure`.

Le coordinateur PostgreSQL de cutover ne référence plus le Snapshot V1
concret. L'adaptation Snapshot V1 vers `ProfileClaimsSeedSourceState` est
confinée au dossier autorisé `Infrastructure/Persistence/HistoricalAccount`.

## Portée

La correction touche uniquement les types nécessaires aux deux passages de
frontière et leurs usages mécaniques. Les huit owners restent séparés et le
cutover 5.1D continue d'utiliser les stores certifiés.
