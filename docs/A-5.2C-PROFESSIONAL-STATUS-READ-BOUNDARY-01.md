# A-5.2C-PROFESSIONAL-STATUS-READ-BOUNDARY-01

## Statut

**BOUNDARY AUDIT OUVERT — CONCLUSION NO GO PROPOSÉE.**

Audit exclusivement documentaire. Aucun composant technique n’est créé ou
modifié.

## Question de frontière

Professional Profile doit décider si un profil par ailleurs visible peut être
exposé publiquement. Cette décision compose deux autorités distinctes :

| Élément de décision | Owner unique |
|---|---|
| état `Active` / `Suspended` | F-05 Professional Status Lifecycle |
| visibilité volontaire `Visible` / `Hidden` | ProfessionalPublicProfile 5.2C |
| décision finale d’exposition | politique additive Professional Profile, consommatrice des deux décisions |

F-05 reste donc l’unique owner de l’état professionnel. Professional Profile ne
peut ni posséder, ni reconstruire, ni corriger cet état.

## Inventaire des frontières existantes

### `ProfessionalStatusWorkflowStore`

Ce port Application expose `read()`, mais il est un port de persistence interne
à F-05. Le même contrat expose également `initialize()` et `append()`. Sa
certification 4.5C porte sur le binding du repository PostgreSQL, son instance
unique, sa résolution lazy et Runtime Health.

Il ne constitue pas une frontière publique de décision :

- il expose le snapshot propriétaire `ProfessionalStatusStoredState` ;
- il expose les états internes `Active` et `Suspended` ainsi que leur version ;
- il mélange lecture et mutations owner ;
- son consumer certifié est le workflow/orchestrateur F-05 ;
- aucune certification ne l’autorise comme dépendance cross-domain.

Le consommer depuis 5.2C créerait une dépendance directe vers la persistence
owner et contournerait la frontière demandée.

### `ProfessionalStatusOrchestrator`

Ce contrat est une frontière de commande. Il accepte une demande de transition
et ne fournit aucune query publique. L’invoquer pour simuler une lecture serait
une violation de responsabilité.

### HTTP F-05

La surface certifiée expose uniquement les transitions `suspend` et
`reactivate`. Elle n’expose aucune lecture de disponibilité publique et ne doit
pas être appelée en boucle interne depuis Professional Profile.

### Events, transport et delivery

Les événements `Suspended` et `Reactivated` sont des notifications de
transition. Les rejouer ou maintenir une projection locale pour reconstruire le
statut courant ne produit pas une autorité de lecture certifiée : lacunes,
ordre, bootstrap et corruption rendraient la décision ambiguë.

## Réponses obligatoires

| Question | Conclusion |
|---|---|
| Quelle autorité possède la décision de statut utilisée pour la visibilité publique ? | F-05 possède exclusivement l’état professionnel ; 5.2C possède sa politique additive d’exposition. |
| Quel contrat public expose cette décision F-05 ? | Aucun contrat public de query fermé n’existe. |
| Ce contrat est-il déjà certifié ? | Non. Seuls le store interne, les commandes, HTTP de transition et les événements sont certifiés. |
| Peut-il être consommé sans lecture SQL directe ? | Pas avec la baseline actuelle sans consommer illégalement le store interne. |
| Préserve-t-il l’unicité des owners ? | Aucun contrat actuel ne le démontre pour un consumer cross-domain. |
| Respecte-t-il les capacités gelées ? | Une consommation directe ne les respecterait pas ; une future query additive et minimale pourrait les préserver. |
| Respecte-t-il les frontières Runtime certifiées ? | Non pour le store actuel ; une future façade de lecture distincte pourrait être composée additivement. |
| Une consommation additive est-elle possible sans modifier F-05 ? | Pas avec les contrats actuels. Elle exige une extension versionnée de la frontière publique F-05, sans modification du lifecycle. |

## Contrat minimal requis

Un amendement d’implémentation ultérieur devrait définir une query publique
versionnée, read-only et owner-scoped, par exemple conceptuellement :

```text
ProfessionalPublicStatusDecisionV1.read(ProfessionalId)
→ Available | Unavailable | Missing | Corrupted | DependencyUnavailable
```

Le résultat ne doit exposer ni snapshot, ni version interne, ni historique, ni
diagnostic SQL. Il doit être fail-closed et rester sous l’ownership F-05.

Cette description ne crée aucun nom contractuel normatif : elle borne seulement
le besoin d’un futur amendement.

## Impacts

| Surface | Impact de l’audit |
|---|---|
| Aggregate / lifecycle F-05 | aucun |
| persistence / migrations | aucun |
| Runtime 5.2C | aucun |
| HTTP 5.2C | reste bloqué |
| Event / Delivery / Outbox | aucun |

## Conclusion

**NO GO.**

La baseline ne contient aucun contrat public certifié de décision de statut
professionnel consommable par 5.2C. Un amendement versionné d’extension de
frontière F-05 doit être explicitement ouvert avant toute implémentation.
