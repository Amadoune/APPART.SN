# A-5.1-IAM-OUTBOX-CONCURRENCY-01 — Root Cause

La table possède deux identités uniques :

- `message_id` ;
- `event_id`.

Deux insertions simultanées identiques passent par deux index uniques.
L'ancienne clause ne déclarait comme arbitre que `message_id`. PostgreSQL
pouvait donc résoudre ce conflit tout en levant `23505` sur l'index unique
`event_id`.

Le défaut a été reproduit pendant la campagne finale 5.1J puis à l'exécution
4/10 de la campagne ciblée répétée.

La clause sans cible absorbe uniquement une violation unique attendue. Après
`rowCount() === 0`, le writer relit la ligne et vérifie event ID, transport
canonique et checksum :

- identité et contenu identiques : `AlreadyApplied` ;
- identité réutilisée avec transport divergent : `DivergentMessage`.

Aucune exception SQL ne devient un succès implicite.
