# A-5.4A Consent Owner-local Runtime Read Boundary — Boundary Audit

## Constat

`ConsentOwnerSourceRuntimeV1` est volontairement une façade de santé locale.
Ses seules responsabilités certifiées sont `availability()` et
`diagnostics()`. Une décision Consent ne lui appartient pas.

Le futur `OwnerLeadContactConsentReaderV1` ne peut cependant pas consommer le
port Persistence `ConsentOwnerSource`, ni son Store, son Mapper ou PostgreSQL.
Une frontière Runtime de lecture owner-scoped manque entre ces deux niveaux.

## Autorité

L'autorité métier demeure `ContactsLeads`. La future frontière ne décidera
rien : elle sélectionnera la révision temporelle certifiée et la réduira vers
un catalogue Runtime fermé. Le Reader public conservera le mapping vers
`LeadContactConsentResultV1`.

## Conclusion

La frontière est réalisable sans modifier les contrats publics, la
Persistence Foundation, la Runtime Foundation de santé ou la migration 072.
Elle nécessite une nouvelle Foundation indépendante et explicitement ouverte.
