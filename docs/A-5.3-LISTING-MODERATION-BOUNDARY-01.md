# A-5.3-LISTING-MODERATION-BOUNDARY-01

## Statut

AMENDEMENT OUVERT — REPRÉSENTATION GO PROPOSÉE

## Owner

`ListingLifecycle` reste l'unique owner de l'éligibilité d'une annonce et de
l'application de toute action sur son workflow.

L'amendement expose deux contrats Application publics :

- `ListingModerationReaderV1` ;
- `ListingModerationCommandGatewayV1`.

Il ne fournit aucune implémentation, composition Runtime ou consommation par
ModerationReports.

## Reader public

```text
ListingId + observedAt
        |
        v
ListingModerationReaderV1
        |
        v
Eligible | Ineligible | Missing | Corrupted | DependencyUnavailable
```

Le Reader ne révèle ni état du lifecycle, ni version, ni projection, ni motif
interne. Tous les résultats autres que `Eligible` sont fail-closed.

## Command Gateway

Entrées exclusives :

- `ListingId` ;
- `ListingModerationActionV1` ;
- `commandId` opaque ;
- checksum canonique ;
- `occurredAt`.

Résultats exclusifs :

- `Applied` ;
- `AlreadyApplied` ;
- `Rejected` ;
- `DivergentIntent` ;
- `VersionConflict` ;
- `DependencyUnavailable`.

Le Gateway est une délégation à l'autorité Listing. Il n'accorde aucune mutation
directe au consommateur.

## Actions fermées

Le catalogue contient uniquement les actions de contrôle déjà présentes dans
F-01 :

- `Suspend` ;
- `RequestChanges` ;
- `Reject` ;
- `Archive`.

Le contrat n'ajoute aucune transition. Une action incompatible avec l'état
courant est traduite par `Rejected` par une future implémentation owner Listing.

## Hors périmètre

- implémentation du Reader ou du Gateway ;
- accès à l'Aggregate ou au Repository Listing ;
- Persistence, migration ou SQL ;
- Runtime, Provider ou binding ;
- HTTP ;
- Event, Delivery ou Outbox ;
- handoff depuis ModerationReports ;
- ouverture de 5.3I.
