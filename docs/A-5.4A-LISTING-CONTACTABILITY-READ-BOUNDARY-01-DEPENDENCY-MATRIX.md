# A-5.4A — Listing Contactability — Dependency Matrix

## Flux cible minimal

```text
ContactsLeads
    -> ListingContactabilityReaderV1
        -> décision owner ListingLifecycle
    -> décision locale d'éligibilité Lead
```

## Matrice

| Producteur | Consumer | Flux | Autorisation actuelle | Condition future |
|---|---|---|---|---|
| ListingLifecycle | ContactsLeads | décision de contactabilité | absente | contrat public V1 certifié |
| ListingLifecycle | Public Projection | faits de publication | certifiée pour projection | ne vaut pas contactabilité |
| Public Projection | ContactsLeads | read model public | interdite | aucune ; finalité incorrecte |
| SearchDiscovery | ContactsLeads | décision de recherche | interdite | aucune ; finalité incorrecte |
| Listing Moderation | ContactsLeads | éligibilité de sanction | interdite | aucune ; finalité incorrecte |
| ContactsLeads local materialization | `CreateLead` | évidence historique | existante | alimentation owner Listing à certifier |
| Professional Core/Profile | ContactsLeads | destinataire et disponibilité professionnelle | hors audit | amendement distinct 5.4A |
| Consent/Anti-abuse owner | ContactsLeads | décision demandeur | hors audit | amendement distinct 5.4A |
| ContactsLeads | Delivery owner-local | message autorisé | hors audit | Foundations ultérieures |

## Dépendances par couche

| Couche | Dépendance autorisable | Dépendance interdite |
|---|---|---|
| Application | contrat public Listing V1 | port interne, Aggregate, Store ou Snapshot Listing |
| Runtime | binding public owner-scoped certifié | Provider ou Runtime Listing interne |
| HTTP | aucune dans cet audit | toute surface ou adaptation HTTP |
| Event | aucune dans cet audit | reconstruction de la décision depuis Events |
| PostgreSQL | aucune cross-domain | SQL Listing depuis ContactsLeads |

## Cycles

Le flux reste acyclique si Listing décide et ContactsLeads consomme. Un retour
de ContactsLeads vers Listing pour modifier la contactabilité créerait un cycle
et demeure interdit.

La résolution Professional, le consentement et la delivery sont des décisions
séparées. Elles ne doivent pas être incorporées au reader Listing afin
d'éviter un service composite sans owner unique.
