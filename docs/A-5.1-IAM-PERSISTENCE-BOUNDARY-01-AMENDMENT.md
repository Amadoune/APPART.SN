# A-5.1-IAM-PERSISTENCE-BOUNDARY-01 — Amendment

## Statut

```text
A-5.1-IAM-PERSISTENCE-BOUNDARY-01
→ OUVERT

Phase 5.1D
→ NO GO CERTIFIÉ
→ OUVERTE

Phase 5.1E
→ FERMÉE
```

## Objet

Supprimer l'unique dépendance `Application → Infrastructure` portée par
`OwnerPersistenceStore`, sans rouvrir fonctionnellement 5.1C et sans modifier
le mécanisme métier 5.1D.

## Changement versionné

Avant :

```text
OwnerPersistenceStore (Application)
  → IdentityAccessCompletionPersistenceSnapshot (Infrastructure)
```

Après :

```text
OwnerPersistenceStore (Application)
  → OwnerPersistenceState (Application)

IdentityAccessCompletionPersistenceMapper (Infrastructure)
  → construit OwnerPersistenceState
```

La campagne Architecture complète a également imposé le maintien du Snapshot
V1 dans son enclave :

```text
HistoricalAccountPersistenceSnapshotV1
  → HistoricalAccountProfileClaimsSeedMapper (enclave Historical Account)
  → ProfileClaimsSeedSourceState (Application)
  → Seed 5.1D
```

Le state du Seed expose uniquement AccountId, email, téléphone, nom et version
historique. Credentials, tokens, vérifications, rôles et consentements restent
dans l'enclave.

`OwnerPersistenceState` conserve exactement :

- `identity` ;
- `version` ;
- `intentId` ;
- `intentChecksum` ;
- `values`.

Les validations d'identité non vide, version positive et checksum SHA-256
lowercase sont inchangées.

## Interdictions respectées

Aucune règle métier, migration, table, index, transaction, idempotence,
optimistic locking, Runtime, HTTP, Event, Delivery, Outbox ou Provider n'est
modifié.
