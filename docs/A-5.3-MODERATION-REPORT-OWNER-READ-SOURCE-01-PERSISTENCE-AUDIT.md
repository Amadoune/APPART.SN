## Persistance réelle de reportId

`reportId` est persisté dans :

```sql
moderation_reports.report_revisions.report_id uuid NOT NULL
```

La clé primaire est :

```sql
PRIMARY KEY (case_id, report_id, case_version)
```

Le payload JSONB de la révision contient notamment l'`actorAccountId` reporter.
Il est protégé par un checksum et reconstruit par
`ModerationPersistenceMapper`.

## Index existants

### Dossier

`moderation_reports.cases.case_id` est la clé primaire. La lecture du dossier
canonique est donc indexée.

### Révisions de rapport

L'index existant est :

```sql
ON moderation_reports.report_revisions
    (case_id, report_id, case_version DESC)
```

Il correspond au chemin futur : `caseId` calculé, puis `reportId`, puis dernière
version. Un index commençant par `report_id` n'est pas requis.

## Chemin de lecture sans scan

```text
reportId
  → deterministicUuid("moderation-case-v1", reportId)
  → cases PK lookup
  → report_revisions index(case_id, report_id, version desc)
  → reporter identity minimale
```

La source ne doit jamais exécuter une recherche globale `WHERE report_id = ?`
ni parcourir tous les dossiers.

## Contrôles de corruption

Retourner `Corrupted` si :

- le dossier dérivé existe mais ne contient pas le `reportId` attendu ;
- plusieurs révisions prétendent être courantes de façon incohérente ;
- le payload n'est pas un objet JSON valide ;
- `actorAccountId` est absent, vide ou invalide ;
- l'identité lue contredit les invariants du dossier canonique.

## Migration

Aucune migration additive n'est nécessaire pour cette source. Modifier 063 ou
ajouter un index report-first serait inutile au chemin déterministe et
augmenterait la surface gelée.
