# Ownership and Transactions

## Ownership

| Élément | Owner unique |
|---|---|
| décision, clôture, Events V1 et Outbox associés | ModerationReports |
| mutation F-01 du Listing | Listing |
| résultat terminal du handoff | ModerationReports |
| `moderation.target-action.completed.v1` | ModerationReports |
| record d'audit durable | AdministrationAudit |

Listing ne produit pas l'Event ModerationReports et AdministrationAudit ne
participe jamais à la transaction métier.

## Transactions futures normatives

### Décision et clôture

```text
mutation ModerationReports
+ Event V1 historique
+ append Outbox ModerationReports
= une transaction owner-locale unique
```

Une erreur Event ou Outbox annule intégralement la mutation. Une mutation non
appliquée n'append rien. Une transaction englobante est rejointe par savepoint.

### Résultat Listing

```text
transaction Listing : transition F-01 puis commit
transaction ModerationReports : intégration du résultat terminal
                              + Event V1 historique
                              + append Outbox puis commit
transaction AdministrationAudit : append indépendant
```

Il n'existe aucune transaction distribuée. Une interruption après le commit
Listing est reprise par le même `commandId` et le même checksum. La convergence
`Applied` / `AlreadyApplied` produit une seule identité logique.

## Garanties

- aucune FK cross-domain ;
- aucun accès SQL cross-owner ;
- aucune émission synchrone vers AdministrationAudit ;
- rollback et savepoint limités à l'owner courant ;
- replay, retry et concurrence convergent sans duplication ;
- divergence de checksum mise en quarantaine fail-closed.
