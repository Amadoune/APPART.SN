# ListingTargetCompleted Atomic Integration Foundation

## Ownership

| Responsabilité | Owner |
|---|---|
| transition F-01 et Gateway | Listing |
| intégration du résultat terminal | ModerationReports |
| `moderation.target-action.completed.v1` | ModerationReports |
| Outbox de l'Event | ModerationReports |

Listing ne produit aucun Event ModerationReports. L'intégrateur terminal ne
dépend d'aucune classe Listing et n'accède ni à son Aggregate, ni à sa
persistence, ni à SQL.

## Séquence transactionnelle

Le Gateway Listing termine et commit sa transaction avant l'intégration :

```text
transaction Listing : application F-01 puis commit
transaction ModerationReports : résultat canonique
                              + TargetActionCompleted
                              + append Outbox puis commit
```

Une erreur Event ou Outbox rollback uniquement l'intégration
ModerationReports. La sanction Listing déjà commitée n'est jamais annulée ou
rejouée comme une nouvelle sanction.

## Normalisation

`Applied` et `AlreadyApplied` convergent vers un unique record terminal
canonique `Applied`. Les statuts `Requested`, `Rejected`, `VersionConflict`,
`AuthorizationDenied`, `TargetIneligible`, `DependencyUnavailable` et
`Quarantined` ne produisent aucun Event de succès.

Le replay conserve le message source, `commandId`, checksum, caseId,
decisionId, corrélation et causalité. Le résultat canonique, l'Event et le
message Outbox convergent sans duplication.

## Event V1 historique

Le type historique `moderation.target-action.completed.v1` est construit par
`ModerationEventV1`. Son payload fermé reste :

- `contractVersion = v1` ;
- `decisionId` ;
- `result = applied` ;
- `targetActionId = commandId` ;
- `targetOwner = Listing`.

L'Event reprend la policyVersion, l'horodatage et la corrélation du Decision
source ; sa causalité est l'eventId Decision. Les tests PostgreSQL vérifient le
payload réellement persisté.

## Atomicité et Outbox

`ModerationAtomicOperationV1` englobe l'append du record terminal canonique et
l'append dans l'Outbox certifiée. `Rejected` ou `DivergentMessage` rollback les
deux écritures. L'Outbox conserve messageId, transport, checksum, advisory
locks, savepoints et résultats fermés existants.

La migration 067, le schéma, le Routing et le Runtime Audit ne sont pas
modifiés.

## Exclusions

Le consumer Audit, le catalogue Runtime Audit à sept Events, AdministrationAudit,
5.3K et 5.3L restent hors périmètre.
