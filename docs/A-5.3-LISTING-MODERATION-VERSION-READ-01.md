# A-5.3-LISTING-MODERATION-VERSION-READ-01

## Statut

AMENDEMENT OUVERT — REPRÉSENTATION GO PROPOSÉE

## Décision de conception

L'option A est retenue.

`ListingPublicationWorkflowStore` est explicitement autorisé comme quatrième
dépendance owner-local de la future implémentation
`OwnerListingModerationCommandGatewayV1`.

Cette autorisation ne crée aucun nouveau contrat, Reader, store, adapter,
binding, schéma ou mécanisme de persistence.

## Justification

`ListingPublicationWorkflowStore` :

- appartient à l'Application de `ListingLifecycle` ;
- est déjà le port propriétaire certifié de F-01 ;
- est indépendant de Laravel, PDO et PostgreSQL ;
- expose une lecture fermée `Found`, `Missing` ou `Corrupted` ;
- fournit, pour `Found`, la version positive déjà utilisée par
  `ListingPublicationOrchestrator`.

Le futur Gateway pourra donc construire légalement la requête F-01 avec :

```text
ListingId
→ ListingPublicationWorkflowStore::read()
→ snapshot.version
→ ListingPublicationOrchestrator::transition(expectedVersion)
```

## Restriction d'usage

L'autorisation porte exclusivement sur `snapshot.version`.

La future implémentation du Gateway ne devra :

- ni inspecter ni interpréter `snapshot.state` ;
- ni retourner le snapshot ;
- ni exposer la version dans son contrat public ;
- ni prendre une décision de lifecycle ;
- ni contourner `ListingPublicationOrchestrator`.

`Missing`, `Corrupted` et toute exception technique devront converger
fail-closed vers les résultats déjà fermés du Gateway.

## Dépendances autorisées du Gateway

La composition owner-local autorisée devient exactement :

1. `ListingModerationIntentStore` ;
2. `ListingModerationIntentTransaction` ;
3. `ListingPublicationOrchestrator` ;
4. `ListingPublicationWorkflowStore`.

Aucune cinquième dépendance n'est autorisée par cet amendement.

## Compatibilité

Restent intégralement inchangés :

- F-01 et `ListingPublicationWorkflow` ;
- `ListingPublicationOrchestrator` ;
- les transitions et résultats de publication ;
- les contrats V1 de modération Listing ;
- les migrations 015, 055 et 068 ;
- Persistence, Runtime Health, HTTP, Event, Delivery et Outbox.

L'amendement ne consomme ni IAM, ni ModerationReports, ni aucun autre domaine.

## Migration et persistence

Aucune migration n'est créée ou modifiée.

Aucune nouvelle persistence n'est nécessaire. Le binding certifié existant de
`ListingPublicationWorkflowStore` est réutilisé sans changement.

## Portée

Cet amendement n'implémente pas le Reader ou le Gateway de modération. Il lève
uniquement le verrou d'autorité relatif à `expectedVersion`.

La seule suite autorisable demeure la reprise explicite de
`A-5.3-LISTING-MODERATION-BOUNDARY-IMPLEMENTATION-01`.
