# A-5.3-MODERATION-QUEUE-OWNER-READ-SOURCE-01 — Discovery

## Statut

DISCOVERY / AUDIT DOCUMENTAIRE — GO PROPOSÉ

## Autorité propriétaire

La collection appartient exclusivement à :

```text
ModerationReports.ModerationQueue
```

Elle est une projection owner-local. Elle ne décide ni de la validité d'un
rapport, ni d'une sanction, ni d'une autorisation IAM.

## Source canonique

La source persistée existe dans la migration 063 :

```text
moderation_reports.queue_items
```

Colonnes disponibles :

- `queue_item_id` ;
- `case_id` ;
- `priority` ;
- `category` ;
- `state` ;
- `lease_id` ;
- `claim_owner_id` ;
- `lease_expires_at` ;
- `source_version` ;
- `updated_at`.

`queue_checkpoints` appartient au mécanisme de projection. Il ne doit pas être
lu ni modifié par la future Query HTTP.

## Filtres fermés réalisables

La future source peut accepter uniquement :

- `state` dans `Available`, `Claimed`, `Completed` ;
- `category` exacte, optionnelle ;
- aucune recherche libre ;
- aucun filtre par `claim_owner_id`, `lease_id` ou donnée externe.

Tout filtre inconnu doit être rejeté fail-closed.

## Ordre déterministe

L'ordre canonique proposé est :

```text
priority DESC, updated_at ASC, queue_item_id ASC
```

Le dernier identifiant garantit un ordre total même lorsque priorité et date
sont identiques.

## Pagination et curseur

La pagination doit être keyset, jamais par offset. Le curseur opaque V1 encode
conceptuellement :

- version du curseur ;
- tuple `priority`, `updated_at`, `queue_item_id` ;
- checksum des filtres normalisés.

Son transport futur doit être canonique, base64url et protégé contre
l'altération. Un curseur invalide, incompatible ou associé à d'autres filtres
doit produire `InvalidCursor`.

La limite proposée est comprise entre 1 et 100, avec une valeur par défaut de
25. Aucune valeur non bornée n'est autorisée.

## Confidentialité

La vue minimale peut exposer :

- `queueItemId` ;
- `caseId` opaque ;
- `priority` ;
- `category` ;
- `state` ;
- indication publique de lease et expiration si le contrat final la retient ;
- `sourceVersion` ;
- `updatedAt`.

Elle ne doit jamais exposer :

- `leaseId` ;
- `claimOwnerId` ;
- checkpoint interne ;
- intent ou checksum ;
- preuve, constat, décision ou identité d'acteur ;
- SQL, PDO, mapper ou snapshot.

## Index existants

La migration 063 certifie :

```text
(state, priority DESC, updated_at, queue_item_id)
```

et un index partiel sur `lease_expires_at` pour les éléments `Claimed`.

Le premier index couvre la lecture par état et l'ordre proposé. Il ne couvre
pas efficacement un filtre catégorie combiné à cet ordre.

## Impact persistence

- lecture par état sans catégorie : aucune migration nécessaire ;
- filtre catégorie certifié à l'échelle : index additif recommandé et considéré
  nécessaire avant certification PostgreSQL de ce filtre ;
- aucune modification de 063 ;
- aucune nouvelle table, FK, cascade ou trigger.

La migration éventuelle devra être autorisée dans une Foundation ultérieure,
après ce Discovery.

## Verdict proposé

**GO PROPOSÉ**

Une source owner read-only, déterministe et paginée est réalisable sans
contourner les fondations. La prochaine étape autorisable serait une Contracts &
Persistence Foundation dédiée, avec décision explicite sur l'index catégorie.
