# A-5.3-MODERATION-HTTP-READ-BOUNDARIES-01 — Discovery

## Statut

NO GO CERTIFIÉ — FERMÉ

## Objet

Rendre exécutables les quatre Queries V1 documentées en 5.3B sans créer de
couche HTTP et sans exposer les sources internes de ModerationReports.

## Inventaire réel

| Query | Contrat documentaire | Source owner disponible | Conclusion |
|---|---:|---|---|
| `ReadOwnModerationReportV1` | oui | aucune résolution `reportId → caseId` | bloquée |
| `ReadModerationQueueV1` | oui | aucune lecture de collection filtrée/paginée | bloquée |
| `ReadModerationCaseV1` | oui | `ModerationCaseStore::read(caseId)` | faisable |
| `ReadModerationDecisionV1` | oui | `ModerationDecisionStore::read/readCurrent` | faisable |

Les stores certifiés exposent :

- une lecture de dossier par `caseId` ;
- une lecture de décision par `caseId` et `decisionId` ;
- une lecture de queue par `queueItemId`.

Ils n'exposent ni recherche par `reportId`, ni liste de queue, ni critères, ni
curseur.

## Interdictions appliquées

L'amendement ne peut pas compenser ces absences par :

- SQL ou PDO dans Application ;
- scan de tables ;
- accès HTTP aux stores ou états de persistence ;
- reconstruction depuis les Events ;
- modification des migrations 063–069 ;
- modification implicite de 5.3D ou 5.3E ;
- reader partiel ou fallback.

## Conclusion

Les quatre frontières ne peuvent pas être rendues exécutables ensemble dans le
périmètre autorisé. Deux sources owner additives doivent être autorisées avant
reprise :

1. source de résolution de rapport propriétaire ;
2. source de lecture de queue filtrée et paginée.
