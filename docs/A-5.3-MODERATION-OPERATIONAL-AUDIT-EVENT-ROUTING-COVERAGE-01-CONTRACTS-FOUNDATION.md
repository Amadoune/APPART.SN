# A-5.3 — Operational Audit Event & Routing Coverage — Contracts Foundation

## Statut proposé

`GO PROPOSÉ`

Cette Foundation est exclusivement contractuelle. Aucun producteur, routeur,
serializer, consumer, Outbox, Provider, Runtime, migration ou SQL n'est créé.

## Catalogue additif V1

| Event V1 | Event Owner | Déclencheur normatif |
|---|---|---|
| `moderation.finding.recorded.v1` | ModerationReports | `RecordModerationFindingV1` retourne exactement `Applied` |
| `moderation.queue-item.claimed.v1` | ModerationReports | `ClaimModerationQueueItemV1` retourne exactement `Applied` |

Les cinq Events V1 historiques conservent leur identité et leur sémantique.

## Payloads minimaux

### FindingRecorded

- `caseId` dans l'enveloppe ;
- `findingId` opaque dans le payload ;
- aggregateVersion ;
- policyVersion ;
- occurredAt et recordedAt ;
- correlationId et causationId.

### QueueItemClaimed

- `caseId` dans l'enveloppe ;
- `queueItemId` opaque dans le payload ;
- aggregateVersion ;
- policyVersion ;
- occurredAt et recordedAt ;
- correlationId et causationId.

Sont interdits : acteur, rôle, texte libre, rationale, preuve, document, URI,
adresse, IP, email, téléphone, token, SQLSTATE et diagnostic.

## Identité et checksum

`eventId` est un UUID déterministe calculé à partir de :

- namespace `moderation-operational-audit-event-v1` ;
- eventType ;
- caseId ;
- aggregateVersion ;
- causationId.

Le checksum SHA-256 couvre l'enveloppe canonique complète et le payload fermé.
Les clés sont triées lexicalement et les dates utilisent ISO-8601 avec
microsecondes et offset explicite.

Un même événement logique conserve le même eventId et le même checksum. Un
eventId identique avec un payload différent constitue une divergence.

## Sémantique de production

Les quatre événements audités — ReportSubmitted, ReportValidated,
FindingRecorded et QueueItemClaimed — sont produits uniquement après un
résultat métier exactement égal à `Applied`.

Aucun Event n'est produit pour `AlreadyApplied`, `DivergentIntent`,
`VersionConflict`, `ForbiddenActor`, `FourEyesViolation`, `Rejected` ou
`DependencyUnavailable`.

Les Commands et leurs résultats restent inchangés.

## Atomicité future

L'implémentation future devra exécuter dans une transaction ModerationReports
owner-local unique :

```text
mutation + Event V1 + append Outbox
```

Un échec Outbox annule la mutation et ne laisse ni Event ni message partiel.
AdministrationAudit ne participe jamais à cette transaction.
