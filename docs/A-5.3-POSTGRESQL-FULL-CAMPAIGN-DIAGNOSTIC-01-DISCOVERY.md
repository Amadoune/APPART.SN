# A-5.3-POSTGRESQL-FULL-CAMPAIGN-DIAGNOSTIC-01 — Discovery

## Statut

DIAGNOSTIC TECHNIQUE OUVERT — CAUSE QUALIFIÉE

## Périmètre observé

La commande directe équivalente à `composer test:postgresql` a été exécutée
avec `--debug`, sans modification du dépôt :

```text
PHPUnit 12.5.31
PHP 8.5.8
PostgreSQL 18.x
658 tests chargés
```

La connexion, le bootstrap, la découverte des tests et les premières migrations
fonctionnent. Des suites appartenant à plusieurs owners ont produit des PASS
continus pendant toute la fenêtre d'observation.

## Cause du résultat non terminal

La campagne a été interrompue par la limite externe de 600 secondes alors
qu'elle progressait encore. Aucun test précis n'est resté bloqué.

Le coût est cumulatif : `PostgreSqlTestEnvironment::migrate()` réapplique
séquentiellement les 69 migrations certifiées et `reset()` tronque l'ensemble
des schémas de test. Ces opérations sont invoquées par de nombreux `setUp()`.
La configuration PHPUnit ne définit ni parallélisation ni timeout interne.

Quatre anciens processus PHP, démarrés le 27 juillet, restent présents. Des
fichiers de barrières historiques subsistent aussi dans le répertoire
temporaire. Ils constituent une dette d'environnement indépendante de Report,
mais la nouvelle campagne a franchi les suites de concurrence et a continué à
progresser : ils ne sont pas démontrés comme cause directe de l'interruption.

## Causes écartées

- authentification PostgreSQL ;
- absence de PostgreSQL 18.x ;
- échec du bootstrap PHPUnit ;
- erreur de migration 063–069 ;
- exception ou échec fonctionnel Report ;
- deadlock SQL observé ;
- blocage sur un test unique ;
- arrêt du runner avant exécution.

## Réponses d'autorité

- **La campagne démarre-t-elle ?** Oui, complètement.
- **Quel composant empêche le verdict ?** La fenêtre d'exécution externe,
  insuffisante au regard du coût séquentiel global ; aucun composant métier
  fautif n'est identifié.
- **Blocage d'infrastructure indépendant de Report ?** Oui : durée du runner et
  hygiène imparfaite des anciens workers. Le second point reste un risque, pas
  une causalité démontrée.
- **Relance sans code ?** Oui, avec une fenêtre d'exécution supérieure et un
  environnement de test préalablement qualifié.
- **Preuve terminale raisonnablement obtenable ?** Oui. La progression continue
  pendant dix minutes le démontre, mais aucun PASS global n'est encore acquis.

## Verdict proposé

**DIAGNOSTIC CONCLUANT — BLOCAGE D'EXÉCUTION, AUCUNE RÉGRESSION REPORT
DÉMONTRÉE.**

Le GO Report demeure non proposable jusqu'à l'obtention effective du résultat
terminal PostgreSQL complet.
