# A-5.5A Search Experience First Foundation — Discovery / Blueprint

## Owner et source owner-locale

La capacité officielle reste Phase 5.5A — Search Experience. Son owner unique
est `SearchDiscovery`.

La première Foundation exécutable recommandée est une Persistence Foundation
owner-locale hybride :

1. un journal append-only des décisions Search finales et versionnées ;
2. un index courant dérivé, optimisé pour la lecture ;
3. une reconstruction de l'index exclusivement depuis le journal owner-local.

Les faits Listing, Property et Media sont des entrées publiques versionnées. Ils
ne deviennent jamais la source de vérité de l'index servi et ne sont jamais lus
depuis leurs Aggregates, SQL ou projections internes.

## Identités et révisions

- `SearchDocumentId` existant : identité stable du document Search ;
- `SearchIndexId` existant : identité de la décision/génération Search ;
- identité source Listing existante, conservée comme référence opaque ;
- `SearchDecision::version` existante : révision monotone positive du document ;
- `SourceRevisionSet` existant : cohérence des sources Listing, Property, Media ;
- `SearchObservedAt` : instant de lecture du contrat public, jamais horloge de
  persistence ni révision ;
- `SearchDocumentIntent` : non requis et non retenu sans use case d'idempotence
  distinct de la décision versionnée.

Aucune nouvelle identité n'est créée par ce Discovery.

## États internes

Les états existants `Visible`, `Hidden` et `Removed` restent internes à Search.
Ils ne sont ni les statuts publics `Found/Empty`, ni des états Listing. Les
motifs source et diagnostics ne traversent aucune frontière publique.

## Invariants candidats

- append-only et révisions strictement monotones par `SearchDocumentId` ;
- idempotence sur identité de décision + version + checksum canonique ;
- même identité/version et même checksum : `AlreadyApplied` futur ;
- même identité/version et checksum différent : divergence fail-closed ;
- version inférieure : obsolete ; version supérieure concurrente : un seul
  gagnant ;
- transaction strictement SearchDiscovery ;
- savepoints compatibles ;
- reconstruction déterministe du courant depuis le journal ;
- aucune PII ni texte privé dans le journal ou l'index.

Le présent document ne matérialise aucun contrat ni composant.
