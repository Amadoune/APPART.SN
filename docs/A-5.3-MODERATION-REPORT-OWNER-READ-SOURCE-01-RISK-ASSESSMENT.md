# A-5.3-MODERATION-REPORT-OWNER-READ-SOURCE-01 — Risk Assessment

| Risque | Niveau | Mesure |
|---|---|---|
| divergence de l'algorithme reportId/caseId | élevé | une seule fonction canonique versionnée et tests de compatibilité |
| report injecté dans un dossier non canonique | élevé | dériver caseId, puis vérifier reportId exact ; `Corrupted` sinon |
| exposition du snapshot | élevé | résultat minimal, aucun état de persistence dans le contrat |
| fuite de l'identité reporter | élevé | source interne owner-scoped ; jamais exposée directement à HTTP |
| énumération de reportId | élevé | future Query homogénéise Missing/non-owner en `NotVisible` |
| payload JSON corrompu | moyen | validation stricte et résultat `Corrupted` |
| indisponibilité PostgreSQL | moyen | `DependencyUnavailable`, fail-closed |
| scan ou index inefficace | faible | lecture PK caseId puis index composite existant |
| modification accidentelle de 063 | élevé | aucune migration dans cette fondation |
| couplage Queue | moyen | source Queue explicitement séparée et NON OUVERTE |

## Risque résiduel

La règle déterministe est actuellement portée par
`CanonicalModerationCommand`. La future implémentation devra éviter une copie
textuelle divergente : elle devra réutiliser une autorité canonique owner-local
ou introduire une abstraction additive strictement compatible, sans modifier
la sémantique de l'orchestrateur.

- intents, checksums et versions internes non nécessaires ;
- diagnostics SQL/PDO ;
- payload complet de la révision.
