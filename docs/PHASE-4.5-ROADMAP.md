# Phase 4.5 — Professional Status Lifecycle Roadmap

1. **4.5A-Discovery** — sélection, blueprint et gates préventifs.
2. **4.5A** — Workflow Foundation : deux états, deux actions exécutables et matrice fermée — certifié GO.
3. **4.5B** — Persistence Foundation : journal append-only PostgreSQL propriétaire — certifié GO.
4. **4.5C** — Runtime Composition : bindings paresseux, alias unique et Runtime Health étendu à 37 capacités — GO proposé.
5. **4.5C-R1** — Transition Context Contract Foundation : acteur, instant, version, rejeu et inspection exacte — GO proposé.
6. **4.5C-R2** — Contextual Persistence Foundation : stockage additif, inspection durable, transaction et concurrence — GO proposé.
7. **4.5C-R3** — Replay Policy Contract Amendment : classification directe par action sans reconstruction — GO proposé.
8. **4.5D** — Runtime Orchestration : lecture, version, décision, append contextuel et rejeu exact — GO proposé.
9. **4.5E** — Event Contract Foundation : deux faits métier fermés, payload V1 minimal, confidentialité et sérialisation canonique — GO proposé.
10. **4.5F** — Event Transport Foundation : payload opaque et port de routage à résultat fermé — GO proposé.
11. **4.5G** — Event Routing Foundation : Inbox durable, idempotence et concurrence — GO proposé.
12. **4.5G-R1** — Delivery Consumption and Runtime Composition : politique fermée et graphe Laravel — GO proposé.
13. **4.5H-R1** — Outbox Owner Schema Foundation : mapping additif `Professionals → professionals` — GO proposé.
14. **4.5H** — Outbox Compatibility : catalogue, mapper, Consumer et Worker générique — GO proposé.
15. **4.5I** — Atomic Event Integration : journal + événement + Outbox dans une transaction — GO proposé.
16. **4.5J** — HTTP Runtime : validation stricte, délégation atomique unique et mapping fermé — GO proposé.

Chaque sprint possède un gate GO indépendant. Un correctif préalable versionné est obligatoire dès qu'un contrat nécessaire manque ; aucun contournement opportuniste n'est autorisé.
