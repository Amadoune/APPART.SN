# A-5.2B-MEDIA-ATTACHMENT-BOUNDARY-01 — Boundary Audit

## Constat

- `CreateMediaCollection` est concret et dépend de `MediaCollectionRegistry` et
  `PropertyCatalog`.
- `AddMedia` est concret et appelle `saveWithMediaReservation`.
- `MediaCollectionRegistry` est un port de persistence, pas une façade métier
  versionnée.
- la création initiale du lifecycle Active est déjà définie hors transitions
  Remove/Archive.

## Frontière cible

`AttachReadyMediaAssetCommandV1` contient : intentId, collectionId déterministe,
propertyId, mediaId déterministe, type Image, checksum canonique, ordre,
caption optionnelle, source fermée, occurredAt et expectedCollectionVersion
optionnelle.

Elle ne contient ni object key, URL, chemin, diagnostic de scan ou binaire.

## Sémantique

1. vérifier la cohérence de la Property par le contrat existant ;
2. créer la collection si elle n’existe pas, sans remplacer une collection ;
3. vérifier l’association immuable collection/property ;
4. réserver définitivement MediaId ;
5. appliquer `MediaCollection::add` ;
6. persister l’intent et la mutation dans une transaction locale Media ;
7. retourner un résultat fermé.

La readiness de l’Asset reste prouvée par Media Ingestion avant l’appel ; F-06
ne devient pas consumer du store Ingestion.
