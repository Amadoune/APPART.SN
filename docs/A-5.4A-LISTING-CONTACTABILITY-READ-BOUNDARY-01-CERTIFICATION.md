# Certification proposée — A-5.4A Listing Contactability Read Boundary

## Périmètre audité

- contrats et sources Listing existants ;
- Public Listing Projection ;
- Search Decision Read ;
- Listing Moderation Reader ;
- modèles Content/SEO ;
- ports, persistence locale et bindings ContactsLeads ;
- documentation Listing, Lead et Phase 5.3 pertinente.

## Résultat

L'autorité métier est attribuée exclusivement à `ListingLifecycle`.

Aucune frontière publique certifiée existante ne satisfait simultanément :

- owner Listing ;
- lecture par `ListingId` ;
- décision minimale de contactabilité ;
- résultats fermés et fail-closed ;
- absence d'exposition du lifecycle ;
- consommation légale par ContactsLeads.

Les composants existants sont rejetés comme substituts :

- `PublicListingQuery` sert le rendu par canonical et expose un read model ;
- `SearchDecisionReader` décide la recherche ;
- `ListingModerationReaderV1` décide l'éligibilité de sanctions ;
- `ListingCatalog` et la matérialisation associée appartiennent au consumer
  ContactsLeads et ne produisent pas l'autorité Listing ;
- Events, snapshots et SQL ne peuvent pas servir à reconstruire la décision.

## Décision documentaire recommandée

Ouvrir ultérieurement un amendement versionné limité à un contrat public
`ListingContactabilityReaderV1` owner ListingLifecycle, puis soumettre
séparément toute Owner Implementation Foundation.

Le présent audit :

- ne crée aucun contrat ;
- ne modifie aucun composant ;
- n'ouvre pas l'amendement d'implémentation ;
- n'ouvre pas Contracts Foundation 5.4A ;
- ne modifie pas la Phase 5.3 gelée.

## Verdict proposé

`NO GO PROPOSÉ — FRONTIÈRE PUBLIQUE ABSENTE — AMENDEMENT VERSIONNÉ REQUIS`
