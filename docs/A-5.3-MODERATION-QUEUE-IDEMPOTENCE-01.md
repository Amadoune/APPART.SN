# A-5.3-MODERATION-QUEUE-IDEMPOTENCE-01

## Statut proposé

`GO PROPOSÉ`

## Objet

L'amendement ajoute l'idempotence durable des claims de la Queue
`ModerationReports` sans modifier les contrats métier V1 ni la migration 063.

## Extension Persistence

La migration additive 064 crée exclusivement :

```text
moderation_reports.queue_claim_intents
```

Colonnes :

- `queue_item_id` UUID ;
- `intent_id` UUID ;
- `intent_checksum` SHA-256 hexadécimal sur 64 caractères ;
- `recorded_at` avec précision microseconde.

La clé primaire `(queue_item_id, intent_id)` rend le journal owner-local et
append-only. La table ne possède ni FK cross-domain, ni cascade, ni trigger.

Le rollback supprime uniquement cette table. La migration 063 reste inchangée.

## Sémantique transactionnelle

Sous le même advisory lock que le claim :

1. le store recherche `(queue_item_id, intent_id)` ;
2. un checksum identique produit `AlreadyApplied` ;
3. un checksum différent produit `DivergentIntent` ;
4. un intent absent poursuit la validation du lease ;
5. le claim et l'append de l'intent sont commités dans la même transaction ;
6. toute erreur ou rollback annule les deux écritures.

Deux intents concurrents convergent vers :

- un `Applied` ;
- un `LeaseConflict`.

## Compatibilité 5.3D / 5.3E

Les paramètres `intentId` et `intentChecksum` sont ajoutés en fin de signature
avec une valeur optionnelle pour préserver les consommateurs certifiés.

- chemin historique sans intent : `Claimed` / `AlreadyClaimed` inchangés ;
- chemin amendé avec intent : `Applied` / `AlreadyApplied` /
  `DivergentIntent`.

Un seul paramètre fourni sans l'autre est rejeté fail-closed.

Le Runtime Queue transmet les deux valeurs sans transformation. Runtime Health,
les bindings, la composition et les diagnostics restent inchangés.

## Frontières préservées

Aucune modification de :

- contrats métier V1 ;
- orchestration ou politique des quatre yeux ;
- Runtime Health ;
- HTTP, Event, Delivery ou Outbox ;
- IAM, Listing, Media, Account, Professional ou Administration Audit ;
- six amendements identifiés en 5.3C.

## Conclusion

Le blocage ayant provoqué le NO GO de 5.3F est techniquement levé par une
extension strictement additive et owner-local.
