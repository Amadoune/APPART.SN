# Anti-abuse Owner-local Runtime Read Boundary — Boundary Audit

## Constat

`AntiAbuseOwnerSourceRuntimeV1` est une façade de disponibilité technique. Ses seules responsabilités sont `availability()` et `diagnostics()` ; elle ne peut fournir une décision anti-abus métier.

Le futur Owner Reader ne peut consommer ni `AntiAbuseOwnerSource`, ni son adapter, son mapper ou PostgreSQL. Il manque donc une frontière Runtime Read owner-scoped entre la Persistence encapsulée et le Reader public.

## Autorité

L'owner demeure `ContactsLeads`. La future frontière ne créera aucune règle : elle effectuera la lecture temporelle owner-locale puis réduira l'état interne vers un résultat Runtime fermé. Le futur Owner Reader réalisera seulement l'adaptation vers le contrat public certifié.

## Conclusion

La frontière est additive et réalisable sans modifier les contrats publics, la Persistence, la Runtime Foundation de disponibilité, Runtime Health ou la migration 073. Une Foundation Runtime Read distincte sera nécessaire et devra être ouverte explicitement.
