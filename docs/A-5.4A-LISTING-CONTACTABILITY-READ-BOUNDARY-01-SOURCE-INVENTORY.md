## Bindings Runtime constatés

- `ListingCatalog` est résolu vers `MaterializedListingCatalog` dans la
  composition existante ;
- `LeadEligibilitySourceDataReader` est résolu vers le store PostgreSQL local ;
- `ListingModerationReaderV1` dispose d'une implémentation owner Listing ;
- `PublicListingQuery` dispose d'un adapter de projection.

Ces bindings prouvent l'exécutabilité de leurs contrats respectifs. Ils ne
permettent ni d'élargir leur finalité ni de les déclarer substituts d'une
frontière de contactabilité.

## Source retenue pour une future frontière

La source de vérité reste l'état owner Listing déjà gouverné par
ListingLifecycle. Une future implémentation devra rester dans cet owner et
retourner seulement une décision fermée.

Aucun choix entre lecture directe owner-local et projection propriétaire
additionnelle n'est pris pendant cet audit. Cette décision relève d'une
éventuelle Owner Implementation Foundation, après certification du contrat.
