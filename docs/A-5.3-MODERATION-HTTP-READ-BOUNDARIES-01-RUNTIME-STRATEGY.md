# A-5.3-MODERATION-HTTP-READ-BOUNDARIES-01 — Runtime Strategy

## Composition cible

```text
Future HTTP
    ↓
Four Query V1 contracts
    ↓
Owner-scoped readers
    ↓
Minimal owner read sources
    ↓
Certified PostgreSQL owner persistence
```

## Bindings futurs

Chaque contrat devra avoir :

- une implémentation unique ;
- un binding singleton ;
- une résolution lazy ;
- aucun alias ambigu ;
- aucun fallback ou Null Object.

Un provider owner-scoped dédié pourra être autorisé après certification des
sources. Il ne devra ni modifier `ModerationRuntimeServiceProvider`, ni étendre
Runtime Health, ni créer de provider HTTP.

## Sources préalables requises

### Report owner lookup

Port minimal read-only capable de résoudre un `reportId` vers une vue owner
nécessaire au filtrage par reporter, sans exposer le snapshot complet.

### Queue owner read source

Port minimal read-only acceptant filtres fermés, curseur opaque et limite
bornée. Il retourne uniquement une page owner contractuelle.

Ces sources nécessitent un audit de persistence. Toute table ou index nouveau
exigerait une migration additive postérieure à 069 et une autorisation
explicite. Aucune migration existante ne peut être modifiée.

## Fail-closed

Toute source absente, corrompue ou indisponible se traduit par un résultat fermé
de Query. Aucun binding ne peut être enregistré tant que sa dépendance réelle
n'est pas résoluble.
