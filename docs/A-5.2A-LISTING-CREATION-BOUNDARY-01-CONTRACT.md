# A-5.2A-LISTING-CREATION-BOUNDARY-01 — CreateListingDraftV1

## Port public normatif

`CreateListingDraftV1::create(CreateListingDraftCommandV1): CreateListingDraftResultV1`

Ces noms sont normatifs mais documentaires ; aucune interface PHP n'est créée.

## Command V1

| Champ | Règle |
|---|---|
| intentId | UUID stable, fourni par l'appelant |
| listingId | UUID stable |
| propertyId | UUID stable et immuable |
| revisionId | UUID stable |
| actorId | identité canonique auto-scopée |
| occurredAt | instant explicite avec offset |
| trigger | valeur fermée `AUTHORING_CREATE` |
| reason | code fermé `INITIAL_DRAFT` |
| origin | `advertiser` |

Le checksum canonique couvre tous les champs, leur version et l'owner logique.

## Results V1

- `Applied(listingId, propertyId, aggregateVersion)` ;
- `AlreadyApplied(listingId, propertyId, aggregateVersion)` ;
- `DivergentIntent(intentId)` ;
- `PropertyUnavailable(propertyId)` ;
- `ListingIdConflict(listingId)` ;
- `InvalidCommand(code)` ;
- `DependencyUnavailable(code)` ;
- `PersistenceFailure(code)`.

Aucun Aggregate, exception PDO ou diagnostic interne n'est exposé.

## Sémantique

- `Applied` signifie intent et Listing validés dans la même transaction ;
- replay avec même checksum retourne `AlreadyApplied` ;
- même intent avec checksum différent retourne `DivergentIntent` ;
- même ListingId déjà associé à une création indépendante retourne
  `ListingIdConflict` ;
- un résultat non appliqué n'écrit ni intent partiel ni Listing partiel.

## Versionnement

Le contrat est V1. Toute modification de champs, résultats ou checksum exige
une nouvelle version compatible ou un nouvel amendement.
