# A-5.3 — Residual Operational Audit Coverage — Contracts Foundation

## Statut représenté

Contracts Foundation ouverte. Ce dossier ne crée ni production d'Event, ni
routing exécutable, ni consumer, ni persistence, ni migration.

## Couverture contractuelle

La couverture résiduelle est limitée aux trois parcours historiques suivants :

| Parcours | Event V1 historique | Condition unique de production |
|---|---|---|
| décision appliquée | `moderation.decision.issued.v1` | `IssueModerationDecisionV1 = Applied` |
| dossier clôturé | `moderation.case.closed.v1` | `CloseModerationCaseV1 = Applied` |
| sanction Listing terminée | `moderation.target-action.completed.v1` | résultat Listing normalisé en `Applied` |

Pour les deux Commands ModerationReports, tout résultat autre que `Applied`
interdit la production d'un Event et l'append Outbox. Cette interdiction couvre
notamment `AlreadyApplied`, `DivergentIntent`, `VersionConflict`,
`ForbiddenActor`, `FourEyesViolation`, `DependencyUnavailable` et `Rejected`.

Pour le handoff Listing, `Applied` et `AlreadyApplied` convergent vers le même
résultat canonique `applied`. Tous les autres résultats restent non producteurs
d'un Event de succès. Un replay conserve le `commandId`, le checksum et
l'identité logique : il ne crée jamais une seconde sanction ni un second Event.

## Compatibilité Event V1

Les trois Events V1 demeurent byte-for-byte compatibles avec leur contrat
historique. Aucun type, version, champ de payload, enveloppe, règle d'identité,
checksum, horodatage, correlationId, causationId ou policyVersion n'est ajouté,
retiré ou renommé.

Une identité logique identique avec un checksum différent est une divergence
fail-closed. Elle ne peut être assimilée à `AlreadyApplied` ou `AlreadyStored`
et ne peut jamais écraser l'Event historique.

## Catalogue Runtime Audit fermé

Le futur Runtime Audit acceptera exactement sept types :

1. `moderation.report.submitted.v1`
2. `moderation.report.validated.v1`
3. `moderation.finding.recorded.v1`
4. `moderation.queue-item.claimed.v1`
5. `moderation.decision.issued.v1`
6. `moderation.case.closed.v1`
7. `moderation.target-action.completed.v1`

Un huitième type, une version inconnue, un checksum invalide, un payload
incomplet ou une destination inattendue est refusé fail-closed.

## Conversion AdministrationAudit

La conversion est mécanique et fermée. Elle ne lit aucun Aggregate, Repository,
store de décision, snapshot ou SQL. Elle sélectionne uniquement l'opération
AdministrationAudit et la clé opaque déjà portée par l'Event :

| Event | Opération | Clé opaque |
|---|---|---|
| ReportSubmitted | `report_submitted` | `reportId` |
| ReportValidated | `report_validated` | `reportId` |
| FindingRecorded | `finding_recorded` | `findingId` |
| QueueItemClaimed | `queue_item_claimed` | `queueItemId` |
| DecisionIssued | `decision_issued` | `decisionId` |
| CaseClosed | `case_closed` | `currentDecisionId` |
| TargetActionCompleted | `listing_handoff_completed` | `decisionId` |

Le contrat `AdministrationAuditAppendV1` et sa persistence restent inchangés.
