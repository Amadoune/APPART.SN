# A-5.2C-PROFESSIONAL-MANDATE-RESOLUTION-01 — Certification

## Décision proposée

**NO GO.**

## Motif

La relation de mandat appartient à l’Aggregate historique `Professional`, mais
aucune frontière publique ne relie l’`AccountId` authentifié à
`RepresentativeId`, puis à un mandat actif et au `ProfessionalId`.

## Surfaces exclues

| Surface | Motif |
|---|---|
| `ProfessionalRegistry` | lookup uniquement par ProfessionalId ; Aggregate et mutations owner |
| `GrantMandate` / `RevokeMandate` | commandes exigeant déjà le ProfessionalId |
| événements de mandat | RepresentativeId sans AccountId ; reconstruction interdite |
| IAM session / AccountRegistry | aucune connaissance du mandat ou du Professional |
| égalité des valeurs AccountId/RepresentativeId | invariant inexistant et non certifié |

## Réponse de certification

- contrat public existant : **NON** ;
- consommation sans SQL direct : **NON** ;
- résolution déterministe et fail-closed existante : **NON** ;
- consommation cross-domain autorisée : **NON** ;
- nouvel amendement nécessaire : **OUI**.

## Garanties

- aucun code, port, adapter, provider, Runtime, HTTP, Event, Delivery, Outbox,
  migration, binding Laravel ou test d’implémentation créé ;
- aucune lecture SQL ;
- aucune modification IAM ou Professional Core ;
- aucune nouvelle décision métier.

## Conséquence

HTTP Foundation reste ouverte en `NO GO CERTIFIÉ`. Une extension publique
versionnée, owner Professional Core, doit être explicitement ouverte avant toute
reprise de l’auto-scope HTTP. Cet audit ne l’ouvre pas implicitement.
