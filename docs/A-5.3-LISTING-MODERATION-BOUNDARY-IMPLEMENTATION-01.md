# A-5.3-LISTING-MODERATION-BOUNDARY-IMPLEMENTATION-01

## Statut

AMENDEMENT RÉOUVERT — REPRÉSENTATION GO PROPOSÉE

## Prérequis

Les deux verrous historiques sont levés par :

- `A-5.3-LISTING-MODERATION-INTENT-SOURCE-01` ;
- `A-5.3-LISTING-MODERATION-VERSION-READ-01`.

## Reader owner Listing

`OwnerListingModerationReaderV1` implémente exclusivement
`ListingModerationReaderV1`.

Il compose le store et le workflow certifiés de F-01. Il traduit la lecture
owner vers le catalogue fermé :

- `Eligible` lorsqu'au moins une action de modération V1 est autorisée par le
  workflow existant ;
- `Ineligible` lorsqu'aucune action n'est autorisée ;
- `Missing` lorsque le Listing est absent ;
- `Corrupted` lorsque la lecture owner n'est pas cohérente ;
- `DependencyUnavailable` lorsqu'une dépendance technique échoue.

Le Reader ne retourne jamais état, version, snapshot ou Aggregate.

## Gateway owner Listing

`OwnerListingModerationCommandGatewayV1` implémente exclusivement
`ListingModerationCommandGatewayV1`.

Sa composition est limitée aux quatre dépendances autorisées :

1. `ListingModerationIntentStore` ;
2. `ListingModerationIntentTransaction` ;
3. `ListingPublicationOrchestrator` ;
4. `ListingPublicationWorkflowStore`.

La séquence exécutée dans une transaction locale est :

```text
read Listing
→ extraire uniquement snapshot.version
→ reserve(commandId, checksum)
→ transition F-01(expectedVersion)
→ complete(result)
→ commit
```

Le Gateway ne lit jamais `snapshot.state`. La décision et la transition restent
exclusivement portées par `ListingPublicationOrchestrator`.

## Résultats fermés

| Observation | Résultat |
|---|---|
| transition F-01 appliquée | `Applied` |
| même commandId et checksum | `AlreadyApplied` |
| même commandId, checksum différent | `DivergentIntent` |
| version F-01 devenue obsolète | `VersionConflict` |
| transition refusée par F-01 | `Rejected` |
| lecture ou persistence indisponible | `DependencyUnavailable` |

## Atomicité et concurrence

La transaction certifiée owner Listing :

- ouvre une transaction locale ou rejoint une transaction englobante par
  savepoint ;
- réserve l'intent sous advisory lock ;
- englobe transition F-01 et résultat terminal ;
- annule intent et transition lorsque la complétion échoue ;
- fait converger deux mêmes commandes concurrentes vers un `Applied` et un
  `AlreadyApplied`.

Aucune transaction distribuée n'est créée.

## Runtime

Le provider existant déclare des singletons et aliases uniques pour :

- `ListingModerationReaderV1` ;
- `ListingModerationCommandGatewayV1` ;
- les deux ports certifiés de la source d'intents.

La résolution demeure lazy. Aucun provider ou composant Runtime Health n'est
ajouté.

## Compatibilité

Restent inchangés :

- F-01, son workflow, son orchestrateur et ses transitions ;
- les contrats V1 ;
- les migrations 015, 055 et 068 ;
- HTTP, Event, Delivery, Outbox et Runtime Health ;
- IAM, ModerationReports et tous les autres domaines.

Aucune migration, persistence ou autorité supplémentaire n'est introduite.
